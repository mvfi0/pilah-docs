    PIL-230 and PIL-176 Review Round — Coverage of My Changes¶

    Diff-coverage evidence for the week-2 TDD claim: how much of the code I added or changed is executed by the tests. Each report is an HTML page from diff-cover, listing every changed line and whether a test ran it.

    PIL-230 mobile: edit form, change history, entry points (as merged, superseded by the next row) pilah-mobile #33 4a52399 vs its base a6cdfe6 325 82.8% as merged, now 100% (next row) pil-230-mobile-diff-coverage.html

    Measured 28 Sep 2026. Test code, migrations and generated files (*.freezed.dart, *.g.dart) are excluded, so tests never count as covering themselves.

    Why each report compares against a fixed commit¶

    These PRs were stacked (#19 → #32 → #52, and #26 → #27 → #33) and have since been squash-merged. After the merges the base branches moved on: origin/feature/pil-222 now points at 07d19d2 (backend) and 64a2735 (mobile). Comparing against the moving branch counted other people's merged code as mine (565 mobile lines instead of 325). Each report therefore compares against the exact commit the PR was built on:

    • #52 against 28fca9c, the head of #32 when PIL-230 branched from it.
    • #19 review round against 9a89c01, the commit that merged staging into #19. Everything after it is my four fixes and their docs; the staging merge itself (other members' code) is left out.
    • #33 against a6cdfe6, the head of #27.

    Closing the mobile gap: 100% on the whole feature¶

    The 82.8% above is #33 as it was merged. By 28 Sep, later PRs had already covered most of those lines, and the remaining gaps sat in code that had been moved or added around my screens (the shared detail sheet, the nasabah history tab, the catat page's back arrow and empty-nasabah submit). pilah-mobile #52 is a test-only PR that brings all of lib/features/pencairan to 100% (898/898 lines, generated *.g.dart serializers included; merged into staging on 29 Sep), which covers every line PIL-176, PIL-222 and PIL-230 introduced on mobile:

    Commit Covers
    54c6877 the pengurus detail sheet: edit refreshes only after a real save; history link only for edited pencairan
    348d7f2 refreshing the nasabah history keeps the list visible with a spinner below
    b619aba submitting before picking a nasabah; the back arrow
    3a851e0 the generated toJson of the pencairan, revision and revision-history responses (JSON round trip back to the API field names)

    Because these tests came after the code, one was checked to be able to fail: making the sheet refresh after any edit turned "leaving the edit form without saving refreshes nothing" red, and renaming the alasan key in the generated revision serializer turned both revision round-trip tests red.

    How to reproduce¶

    Backend, from the PR's worktree:

    coverage run --source=api manage.py test
coverage xml -o cov.xml
diff-cover cov.xml --compare-branch=28fca9c \
  --exclude "*/tests.py" "*/test_*.py" "*/migrations/*" \
  --format html:pil-230-be-diff-coverage.html

    Mobile (Flutter 3.38.3, the CI version):

    flutter test --coverage
# Windows writes backslashes into lcov.info; normalise them to / first
diff-cover coverage/lcov.info --compare-branch=a6cdfe6 \
  --exclude "*.freezed.dart" "*.g.dart" \
  --format html:pil-230-mobile-diff-coverage.html
